你是一名高温合金领域的专家。下面提供了一组*可能同物异名*的实体候选，请你在确保准确的前提下，对它们进行**合并分组**与**规范名**确定。

## 你将收到的输入（JSON）
$payload

- `entities[*].id`: 实体在图中的唯一ID（必须用于输出）
- `entities[*].name`: 当前名称（可能是别名/缩写/商标）
- `entities[*].aliases`: 已知别名列表（可为空）
- `entities[*].desc`: 消歧后的精炼描述（若无，也可能为空）
- `entities[*].type`: 类型（如 alloy/material/org 等，可为空）

## 任务
1. **只在有较高把握时合并**：若候选中混入了不同材料/对象，请分成不同子组。
2. **为每个子组给出行业通行的 `canonical_name`**：
   - 优先标准号（UNS/GB/AMS/ISO 等）。
   - 其次国际常用商标名（如 Inconel 718）。
   - 若都无法确定，选择最常见且不含歧义的名称。
3. **保持可溯源**：输出时必须给出每个子组包含的 `member_ids`（对应输入的 id）。
4. **如无法合并**：将每个实体各自成组（每组仅1个）。

## 输出
仅输出**一个**JSON对象，**不要**包含任何解释性文本或代码块标记。格式必须满足：

```json
{
  "groups": [
    { "canonical_name": "<字符串>", "member_ids": ["<id1>", "<id2>", "..."], "rationale": "<可选，合并依据>" }
  ]
}
````

* `groups.length` 可为 1..N。
* `member_ids` 必须来自输入 `entities[*].id`；不要编造新ID。
* 如你**不建议**合并，请把每个成员拆分为单独的组。

## 评判准则（内部）

* 仅在语义与用途高度一致时合并。
* 名称冲突时，以**标准号**为优先规范名。
* 若描述缺失但名称明显等价（如 “GH4169” 与 “Inconel 718”），可判定为同组，并在 `rationale` 说明依据。
* 不要合并明显不同的实体（如 “Inconel 718” 与 “Incoloy 800”）。
* 不要合并信息不足的实体（如 “Alloy 625” 与 “Inconel 625”），除非你能**非常有把握**它们是同物异名。
* 不要合并类型不同的实体（如 “公司” 与 “材料”）。
* 不要合并描述冲突的实体（如 “镍基高温合金” 与 “铁基高温合金”）。
* 不要合并明显不同的标准号（如 “GH4169” 与 “GH3030”）。
* 不要合并明显不同的化学成分（如 “镍基” 与 “铁基”）。
* 不要合并明显不同的用途（如 “高温合金” 与 “不锈钢”）。
* 不要合并明显不同的牌号（如 “Inconel 718” 与 “Inconel 625”）。
